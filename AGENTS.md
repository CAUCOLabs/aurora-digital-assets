
# AGENTS.md

This repository uses AI coding agents to assist with implementation, documentation, UI prototyping, testing, and refactoring.

All agents must follow the project principles below.

## Project Identity

Project name: **Aurora Digital Assets**  

Concept name: **Bank-Integrated Crypto Wallet Framework**

Aurora Digital Assets is a concept prototype for integrating a regulated digital assets wallet module inside an online banking environment.

This is not a crypto exchange, not a trading platform, and not a real bank product.

## Core Principles

1. Banking-first user experience

2. User protection and education

3. Compliance-by-design

4. Transparency in fees, risk, custody, and transactions

5. Controlled and auditable external wallet withdrawals

6. No gamification, no leverage, no speculative UI patterns

7. Clear separation between mock prototype and real financial systems

## UI Direction

The UI should feel like a Nordic online banking portal:

- sober

- trustworthy

- calm

- structured

- conservative

- blue/grey/white visual language

- clear navigation

- table-based account views

- simple cards

- low visual noise

Do not create a Binance/Coinbase-style trading app.

Do not use neon crypto aesthetics.

Do not use real bank names, logos, colors, or copyrighted UI assets.

Use fictional branding only.

Recommended fictional bank name: **Aurora Bank**.

## Compliance Language

Use responsible wording:

- digital assets

- custody

- volatility

- tax reporting

- risk warning

- external wallet transfer

- compliance review

- audit trail

- transaction monitoring

- user protection

Avoid promotional wording:

- moon

- pump

- high returns

- guaranteed profit

- investment opportunity

- 100x

- passive income

- financial freedom

## Security Boundary

This project must not include real private keys, seed phrases, API keys, bank credentials, or real user financial data.

All data must be mock or simulated.

## Development Rules

- Prefer clear, readable code over clever code.

- Keep modules small.

- Use explicit naming.

- Document architectural decisions.

- Keep mock data separate from application logic.

- Ensure UI copy makes clear that this is a concept prototype.

- Do not connect to real banking APIs.

- Do not connect to real crypto custody providers unless explicitly documented as a future integration.
